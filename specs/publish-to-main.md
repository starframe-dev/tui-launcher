# Подготовка tui-launcher к публикации в main

## Контекст

Локальная папка проекта не содержит Git-метаданных, а GitHub-репозиторий пуст. Перед начальным commit обнаружены абсолютные `replace` в `go.mod`, из-за которых проект не собирается вне этой машины, и тест, который требует заранее собранный бинарник из `bin/`. В корне также лежат бинарники и временные CueTTY-артефакты.

## Цель

Подготовить минимальный переносимый исходный проект, проверить тесты и vet, затем создать начальный commit и отправить ветку `main` в `https://github.com/starframe-dev/tui-launcher`.

## Что изменится

1. `go.mod`, `go.sum`, `warp/warp.go` — заменить абсолютные локальные зависимости на опубликованные модули и согласованные версии.
2. `main.go` — получать задачи асинхронно через typed Bubbletea message и менять состояние модели только в `Update()`.
3. `cue_test.go` — сделать тест самодостаточным: собирать приложение из исходников во временную директорию перед запуском.
4. `.gitignore` — исключить `.DS_Store`, собранные бинарники и CueTTY-артефакты.
5. Git metadata — создать начальную ветку `main`, добавить исходники, сделать initial commit и push.

## Детали реализации

1. Использовать опубликованные версии `github.com/starframe-dev/warp` и `github.com/starframe-dev/portalis`; убрать абсолютные `replace`.
2. В `warp/warp.go` использовать канонический импорт `github.com/starframe-dev/portalis`.
3. `Init()` возвращает typed message с задачами; обработчик `Update()` устанавливает `tasks` и `initialized`, не мутируя модель из фоновой goroutine.
4. В тесте собрать текущий пакет в `t.TempDir()` и запустить собранный executable через CueTTY.
5. Не добавлять Mach-O бинарники, `.DS_Store` или каталоги `cuetty-artifacts/` в Git.
6. Проверить `go test ./...`, `go vet ./...` и чистоту состава staged files до commit.
7. Выполнить push initial commit в `origin/main`; никаких force-push операций.

## Критерии приёмки

- [ ] В manifest нет абсолютных локальных путей.
- [ ] Задачи загружаются в модель через Bubbletea message без фоновой мутации модели.
- [ ] `go test ./...` проходит без заранее созданного бинарника.
- [ ] `go vet ./...` проходит.
- [ ] В commit нет бинарников, `.DS_Store` и тестовых артефактов.
- [ ] Initial commit доступен в GitHub-ветке `main`.
